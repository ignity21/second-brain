** Radon 的代码度量
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:ANKI_NOTE_ID: 1785249007074
:ANKI_NOTE_HASH: 22f5d4314d43df24d743cc98affb5ac8

*** Front
Radon 是什么？它可以计算哪些 Python 源代码度量？

*** Back
Radon 是一个用于分析 Python 源代码的工具，可以计算：

- McCabe 复杂度，也就是圈复杂度（cyclomatic complexity）
- 原始度量（raw metrics），包括 SLOC、注释行数和空白行数等
- Halstead 度量
- 可维护性指数（Maintainability Index），即 Visual Studio 使用的那种指数

** cProfile inflates call-heavy code
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
cProfile says a tiny helper function called millions of times is the hot spot. Before inlining it, what should you check, and why?

*** Back
Confirm with a sampling profiler (py-spy, ~profiling.sampling~). cProfile is deterministic: it adds a fixed cost to every call, so call-heavy code looks several times worse than it is (measured: 0.19 s became 1.10 s while an inline loop stayed 0.11 s). Sampling preserves the proportions.

** Profiling a live Python process
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
A production Python service is slow (or stuck) right now and must not be restarted. How do you see where it spends its time?

*** Back
Attach a sampling profiler from outside: ~py-spy dump --pid PID~ for current stacks, ~py-spy top~ or ~py-spy record --pid PID~ for a profile; on 3.15+ also ~python -m profiling.sampling attach PID~. Attaching needs ptrace permission (sudo when ~ptrace_scope~ is 1; ~--cap-add SYS_PTRACE~ in Docker).

Source: Python Profiling

** Waiting time missing from a profile
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
A function spends most of its time waiting on a socket, yet ~py-spy record~ barely shows it. Why, and how do you include it?

*** Back
py-spy skips idle threads by default, so it shows CPU time; add ~--idle~ to include waiting. Defaults differ between tools: cProfile measures wall time, and ~profiling.sampling~ defaults to ~--mode wall~ (~--mode cpu~ drops waiting).

Source: Python Profiling

** timeit and the garbage collector
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
Why can ~timeit~ make allocation-heavy code look faster than it is in production, and how do you correct for it?

*** Back
~timeit~ disables the garbage collector while timing, so GC pauses are not counted. Put ~gc.enable()~ at the start of the setup string when GC cost matters.

*** Front
~python -m cProfile app.py~ on Python 3.12, where ~app.py~ does its work in a ~threading.Thread~. Do the worker's functions appear in the output? What about 3.11?

*** Back
3.12+: yes. cProfile is built on ~sys.monitoring~, which covers every thread. 3.11: no, only the thread that enabled the profiler (here the main thread).

** Profiling one slow request among many
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
One request in a hundred is slow, and it involves several threads and asyncio tasks. Which kind of profiler fits, and why not cProfile or a sampling profiler?

*** Back
An event tracer such as VizTracer: it records every call with timestamps, so you can see that request's timeline, gaps and overlaps. cProfile and sampling profilers aggregate over the whole run, so one slow request is averaged away.

Source: Python Profiling

** VizTracer loses the start of a long run
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
A VizTracer trace of a long run is missing everything from the beginning. Why, and what is the better fix than just raising the limit?

*** Back
Its buffer is circular (1,000,000 entries by default), so older entries are overwritten. Trace a narrow window instead: start and stop it in code (~with VizTracer(...)~), or filter with ~--max_stack_depth~, ~--include_files~ or ~--min_duration~. Raise ~--tracer_entries~ only if needed.

** Why dicts keep insertion order
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
How is a CPython ~dict~ laid out so that iteration follows insertion order? Does a ~set~ keep order too?

*** Back
Two arrays: a dense entries array of ~(hash, key, value)~ appended in insertion order, and a sparse hash table whose slots only hold indices into it. Iteration walks the entries array. A ~set~ is a plain hash table of keys with no entries array, so it has no order.

Source: Python dict and set Internals

** When a dict resizes
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
In current CPython, when does a dict's hash table resize, and what sizes does it take?

*** Back
When it is about two-thirds full; sizes are powers of two starting at 8 (resizes happen at the 6th, 11th, 22nd, 43rd insert). Older material showing 8 → 18 → 39 → 81 describes Python 2. Resizing is O(n) once in a while, O(1) amortized.

Source: Python dict and set Internals

** __eq__ without __hash__
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
A class defines ~__eq__~ but not ~__hash__~ . What happens when you put an instance in a set?

*** Back
~TypeError~ (in 3.14: "cannot use 'A' as a set element (unhashable type: 'A')"): defining ~__eq__~ sets ~__hash__~ to ~None~ . Define ~__hash__~ from the same (immutable) fields that ~__eq__~ compares.

** Circular imports
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
Module ~a~ imports ~b~ , and ~b~ runs ~from a import name~ at the top. Why can this fail with ImportError even though ~name~ is defined in ~a~ ?

*** Back
~a~ is put into ~sys.modules~ before its code finishes. When ~b~ imports it back it gets the partially initialized module, and ~name~ is not defined yet if it comes after ~import b~ in ~a~ . Move the import into the function that needs it, or restructure.

Source: Python Import System

** Relative import in a script
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
~python pkg/run_me.py~ fails with "attempted relative import with no known parent package" because the file contains ~from . import helper~ . Why, and how do you run it?

*** Back
Run as a script, the module is named ~__main__~ with no parent package, so the relative import cannot be resolved. Run it as a module from the project root: ~python -m pkg.run_me~ , which sets ~__package__~ .

** Shadowing the standard library
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
A script in a directory that also contains ~json.py~ does ~import json~ and gets errors about missing ~json.loads~ . Why?

*** Back
~sys.path[0]~ is the script's directory, searched before the standard library, so the local ~json.py~ is imported instead. Rename the file (and delete its ~__pycache__~ ), or run with ~python -I~ .

** SQLAlchemy 2.0 raw SQL
:PROPERTIES:
:ANKI_NOTE_TYPE: CC Basic
:END:

*** Front
In SQLAlchemy 2.x, ~conn.execute("SELECT * FROM t")~ raises ~ObjectNotExecutableError~ , and inserts made inside ~with engine.connect() as conn:~ disappear. Why, and what is the fix for each?

*** Back
- Plain strings are no longer executable: wrap them in ~sa.text(...)~ and bind parameters ( ~:name~ ).
- Every connection runs in a transaction that is rolled back on exit unless you call ~conn.commit()~ ; or use ~with engine.begin() as conn:~ , which commits on exit.

Source: SQLAlchemy
