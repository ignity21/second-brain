# second-brain

个人知识库：org-roam 笔记 + Anki 卡片，与 AI agent（Claude Code 等）协作维护。本文件是给自己看的使用说明；agent 遵守的详细规则在 [AGENTS.md](AGENTS.md)。

## 目录

| 位置 | 内容 |
|---|---|
| `roamnotes-v2/` | org-roam 笔记库。大写开头的目录是大类，每个大类有同名根索引（如 `Statistics/statistics.org`） |
| `roamnotes-v2/Learning/` | 学习路径：按学习顺序串起各大类的笔记，见下文 |
| `roamnotes-v2/Unsorted/` | 未分类的速记，定期归类 |
| `ankinotes/` | Anki 卡片，每个领域一个文件 |
| `inbox/` | 待处理的学习材料（不进 git） |
| `projects/` | 笔记配套的示例代码 |
| `.agents/tasks/` | 多轮工作的任务文件，顶部 `Status:` 行写当前状态和下一步 |
| `.agents/learning-goals.md` | 各领域学到什么程度，决定入库深度 |
| `scripts/`、`publish/` | 维护脚本、笔记站导出与构建 |

笔记站：推送到 `master` 且改动了 `roamnotes-v2/` 时，GitHub Actions 自动构建发布，手机上也能看。

## 常用工作流

### 按学习路径学习或复习

1. 定主题：「近期要学 / 复习 X，做一条学习路径」。agent 在 `Learning/` 建 `X Learning Path`，把相关笔记按前置依赖由浅入深排好，每步一个核心问题，阶段末尾列对应的 Anki 卡片。
2. 陪学：「继续 X 路径」。agent 从第一个未勾选的步骤开始，一步一步来：
   - 开场：打开这一步的笔记，说出这一步要回答的核心问题。
   - 讲解：在笔记已有的内容上接着讲；讲机制时先举最小的具体例子，再引入术语。说「不懂」会换一种讲法或缩小例子；文字讲不清的动态过程，可以要一个逐步播放的 HTML 演示。
   - 检验：说「考我」，agent 出一道和笔记略有不同的题，等你答完再讲。答错或卡住的地方记为卡点。
   - 收尾：说「这步学完了」，agent 勾选这一步、更新进度，处理这一步的「待改」项，把卡点做成卡片并推送到 Anki。已经会的步骤说「这步跳过」。
3. 进度：保存在路径文件里，下次说「继续 X 路径」就从停下的地方接着学。也可以自己在 Emacs 里勾选；推送后笔记站同步。笔记站是只读的，手机上只能看。
4. 修笔记：步骤下的「待改」是排路径时发现的旧笔记问题，学到这一步时一起改。事实错误直接改；整篇重写按自己在这一步的卡点来，不让 agent 提前代写。

路径笔记都带 `:learning:` 标签，在 org-roam-ui 图谱里可按标签隐藏。

### 从学习材料入库（收件箱）

新知识从外部材料进来时用；复习已有笔记用上面的学习路径。`inbox/` 只放待处理的原始材料，不进 git；已经写成笔记、只是还没分类的，放 `roamnotes-v2/Unsorted/`。

**收集**：读到想入库的文章、视频、书的章节时，存一份材料到 `inbox/` 根下，一份一个文件，文件名能认出主题即可（如 `inbox/tcp-handshake.md`）。

- 网页：直接在浏览器点「summarize page」，把总结存成 `.md`。试过几次，这样得到的总结比原文更好用：按「问题 → 机制」组织，术语标准。
- 也可以放原文、视频字幕、幻灯片或 PDF。

**处理**：说「处理收件箱」。一次只处理一份材料，过程是和 agent 一起读一遍：

1. 选材料：有多份时 agent 让你挑一份。
2. 定深度：这个领域如果还没记在 `.agents/learning-goals.md`，agent 会先问用途和档位（不需要 / 知道 / 能判断 / 能写），最多 3 个问题，答案记下来以后不再问。
3. 逐块读：agent 把材料按小节分块，一次给一块原文，附上它的判断：哪里有错、和旧笔记冲突的地方、打算收还是不收。你确认后再进入下一块。读的时候随时说出卡点，比如「原来以为 X」「这里没懂」，agent 会用你的原话记下来。这些卡点决定笔记写什么，也会变成卡片。觉得后面都没问题，就说「剩下都没问题」，跳过剩余部分。
4. 收口：agent 问一次「卡点都提完了吗？」，你确认后才开始写笔记。
5. 产出：
   - 笔记：按档位写，优先并入已有笔记；可查询的细节不抄录。没有值得收的内容时，0 条产出也正常。
   - 卡片：每个卡点做一张卡；agent 再就其他要点出最多 3 道题，一次一道，你可以作答，也可以跳过。
6. 归档：处理过的稿子移到 `inbox/archive/<日期>/`，之后每次处理收件箱时，删掉超过 10 天的归档。以笔记为准，不回头看稿子。

最后 agent 会列出新增或修改的笔记、生成的卡片、记录的学习目标，以及没收录的部分和原因。

### 在库里直接提问

直接问即可。agent 会先查相关笔记，在已有内容上接着讲，并指出与旧笔记冲突的地方。

### Anki 卡片

「给 X 笔记做卡片」或「改某张卡」。卡片在 `ankinotes/<领域>.org`，每个大类一个 Deck。写完并通过检查后，agent 会用 anki-editor 推送到 Anki；需要先打开 Anki（AnkiConnect 插件要启用），没打开时 agent 会说明未推送。自己在 Emacs 里推送用 `C-c n k p`。

### 找回没做完的事

「还有什么没做」或「接着之前的 X」。agent 会列出未完成的任务文件：

```sh
rg -n '^Status:' .agents/tasks/ | rg -v 'Status: Complete'
```

### 检查笔记

`python3 scripts/check_notes.py` 检查全库：失效链接、标题重名、主索引树（唯一主父节点、可达性、层级、出度）、笔记间链接、缺少的 TOC 和行内标记。后面加文件名时，只报告与这些文件有关的问题。agent 每次改完笔记都会跑一遍。

## 项目内置 skill

agent 按需加载的工作流，在 `.agents/skills/`（`.claude/skills/` 中有对应链接）：

| skill | 什么时候用 |
|---|---|
| `learning-path` | 建或改学习路径；「继续 X 路径」「考我」 |
| `inbox-processing` | 「处理收件箱」 |
| `cc-note-writing` | 写新笔记、整理或改写笔记内容 |
| `anki-cards` | 做卡、改卡、推送到 Anki |
| `notes-site` | 改笔记站前端或发布流程，推送后确认部署 |
| `note-migration` | 从旧库 `roamnotes/` 迁移；清理旧库后删除 |

## 相关仓库

- `~/.config/doom`：Doom Emacs 配置，org-roam 设置在 `modules/cc/notes`。
- `~/repos/org-roam-ui`：笔记站前端 fork，分支约定见 `notes-site` skill。
