# 网页材料采集提示词

在浏览器侧边栏或 claude.ai 中边读网页边使用，产出 `inbox/` 下的一份材料（`source.md` + `questions.md`），之后在仓库里「处理收件箱」。此阶段只采集正文和引出疑问，不总结、不提炼：提取依据是用户的疑问和已有笔记，网页端都看不到。

````
帮我把这篇网页学习材料存进知识库收件箱。不要总结，不要提炼要点，也不要改写原文。提取由我之后根据自己的疑问来做。

## 第一步：存正文（source.md）
- 把网页正文转成 Markdown，保留原文的段落顺序、代码块、表格、图注和正文里的关键链接。
- 只删页面杂项：导航、广告、推荐阅读、评论区、订阅或登录提示、页脚。
- 正文开头写：标题、URL、作者（如果有）、发布日期（如果有）、抓取日期。
- 如果我说只读了其中几节，就只存那几节，并注明省略了哪些部分。

## 第二步：引出我的疑问（questions.md）
按顺序做，每次只问一个问题，等我回答后再继续：
1. 根据文章里涉及机制、取舍或故障的内容，出 3 道「预测题」（不考定义和 API），先让我在没看答案的情况下作答。把我的回答原样记下来，先不要批改。
2. 问我：哪里没看懂？原来是怎么理解的？哪个结论让我意外？
3. 问我：有没有准备用在实际项目里、但还拿不准怎么选的地方？

只记我说过的话，不要替我补充疑问。如果我说没有疑问，就写「无」。

questions.md 的格式：
```
# 来源
<标题> — <URL>
# 疑问
- [没懂] ...
- [原以为] ...
- [拿不准] ...
- [预测题] <题目> / 我的回答：<原话>（未批改）
```

## 输出
分两个代码块输出，分别标注文件路径：
- `inbox/<YYYY-MM-DD>-<英文短 slug>/source.md`
- `inbox/<YYYY-MM-DD>-<英文短 slug>/questions.md`
````
