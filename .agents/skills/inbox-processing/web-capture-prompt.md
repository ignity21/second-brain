# 网页材料采集提示词

边读网页边在浏览器侧边栏或 AI 聊天网页中使用，产出 `inbox/` 下的一份材料（`source.md` + `questions.md`），再在仓库里「处理收件箱」。这一步只采集正文、引出疑问，不总结、不提炼。

````
帮我把这篇网页学习材料存进知识库收件箱。不要总结、提炼或改写原文。

## 第一步：存正文（source.md）
- 正文用我发来的页面文本或选中部分；只有网址时自己读取。读不到正文（登录页、付费墙、只有摘要）就告诉我，不要凭网址、标题或记忆补写。
- 转成 Markdown，保留段落顺序、代码块、表格、图注和关键链接。纯文本丢了格式时，按内容恢复代码块和标题，还原 `&lt;` 等转义；拿不准的地方标注出来。
- 只删页面杂项：导航、广告、推荐阅读、评论区、订阅或登录提示、页脚。
- 开头写标题、URL、作者和发布日期（有就写）、抓取日期。没有 URL 先问我，不要编。
- 正文像被截断时注明并提醒我补发；分几次发来的按顺序合并。我说只读了其中几节，就只存那几节并注明省略了哪些。

## 第二步：引出我的疑问（questions.md）
按顺序一次问一个，等我回答再继续：
1. 就文章里的机制、取舍或故障出最多 3 道预测题（不考定义和 API），让我先作答。答案必须能在正文里找到：场景只用文中出现的设备、协议和机制；文章只提出、留到以后讲的问题不出题。我的回答原样记录，不批改。
2. 哪里没看懂？原来是怎么理解的？哪个结论让我意外？
3. 有没有准备用在项目里、但拿不准怎么选的地方？

只记我说过的话，不替我补充疑问；我说没有就写「无」。格式：
```
- [没懂] ...
- [原以为] ...
- [拿不准] ...
- [预测题] <题目>（依据：<原文小节>） / 我的回答：<原话>（未批改）
```

## 输出
两个代码块，分别标注路径：
- `inbox/<YYYY-MM-DD>-<英文短 slug>/source.md`
- `inbox/<YYYY-MM-DD>-<英文短 slug>/questions.md`
````
