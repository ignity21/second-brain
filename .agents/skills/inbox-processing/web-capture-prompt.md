# 网页材料采集提示词

在浏览器侧边栏或任意 AI 聊天网页中边读网页边使用，产出 `inbox/` 下的一份材料（`source.md` + `questions.md`），之后在仓库里「处理收件箱」。此阶段只采集正文和引出疑问，不总结、不提炼：提取依据是用户的疑问和已有笔记，网页端都看不到。

````
帮我把这篇网页学习材料存进知识库收件箱。不要总结，不要提炼要点，也不要改写原文。提取由我之后根据自己的疑问来做。

## 第一步：存正文（source.md）
- 正文来源：我发来的页面文本或选中的部分；如果只有网址，就自己读取该网页。读不到、只读到登录页或付费墙提示、只拿到摘要时，直接告诉我，让我把正文发给你；不要凭网址、标题或自己的记忆补写正文。
- 把网页正文转成 Markdown，保留原文的段落顺序、代码块、表格、图注和正文里的关键链接。如果正文是丢失了格式的纯文本，就按内容恢复代码块和标题，并把 `&lt;` 等转义还原；拿不准的地方标注出来，不要猜。
- 如果正文在句中突然中断，像是被截断了，就在 source.md 里注明，并提醒我把剩下的部分发给你。我分几次发来的内容，按顺序合并成一份。
- 只删页面杂项：导航、广告、推荐阅读、评论区、订阅或登录提示、页脚。
- 正文开头写：标题、URL、作者（如果有）、发布日期（如果有）、抓取日期。消息里没有 URL 时先问我，不要编。
- 如果我说只读了其中几节，就只存那几节，并注明省略了哪些部分。

## 第二步：引出我的疑问（questions.md）
按顺序做，每次只问一个问题，等我回答后再继续：
1. 根据文章里涉及机制、取舍或故障的内容，出最多 3 道「预测题」（不考定义和 API），先让我在没看答案的情况下作答。每道题的答案都要能在这篇正文里找到：场景只用文中出现过的设备、协议和机制，不额外加文中没有的环节；文章只提出、说以后再讲的问题不出题。把我的回答原样记下来，先不要批改。
2. 问我：哪里没看懂？原来是怎么理解的？哪个结论让我意外？
3. 问我：有没有准备用在实际项目里、但还拿不准怎么选的地方？

只记我说过的话，不要替我补充疑问。如果我说没有疑问，就写「无」。

questions.md 的格式：
```
# 来源
<标题> — <URL>
# 疑问
- [没懂] ...
- [原以为] ...
- [拿不准] ...
- [预测题] <题目>（依据：<原文小节标题>） / 我的回答：<原话>（未批改）
```

## 输出
分两个代码块输出，分别标注文件路径：
- `inbox/<YYYY-MM-DD>-<英文短 slug>/source.md`
- `inbox/<YYYY-MM-DD>-<英文短 slug>/questions.md`
````
