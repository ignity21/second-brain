# 处理收件箱

`inbox/` 位于仓库根目录（已 gitignore），存放待处理的原始材料；与 `roamnotes-v2/Unsorted/`（未分类的正式笔记）无关。

## 材料约定

一份材料一个子目录，如 `inbox/2026-10-15-tcp-handshake/`。网页材料通常是浏览器「summarize page」生成的总结，存为 `source.md`；也可以是原文、文稿或幻灯片 PDF。不要求用户另写疑问文件，需要的信息在处理时提问。

各领域的学习角度、用途和档位记录在 [`.agents/learning-goals.md`](../../learning-goals.md)，同一领域可按子领域分档。档位（不需要 / 知道 / 能判断 / 能写）的定义见 `cc-note-writing`「掌握目标与载体」。

## 向用户提问

只问答案会改变产出的问题，一次集中问完，最多 3 个，按以下优先级：

1. **领域角度、用途与档位**：仅当该领域或子领域不在 `learning-goals.md` 中，或材料明显超出已记录的用途时问。
2. **卡点**：「读的时候有没有没懂、意外或和原来理解不一样的地方？没有就跳过。」
3. **冲突与存疑**：总结与已有笔记矛盾，或总结中的说法存疑且 AI 无法核实时，问以哪个为准。
4. **个人背景**：仅在「能判断」或「能写」且材料涉及选择时，问打算用在哪里、有什么约束。

不问 AI 能自己核实或决定的事：事实对错（先自己核对）、笔记位置和标题（决定后在回复里说明）。

回答记到哪里：

| 回答 | 记录位置 |
|---|---|
| 领域角度、用途、子领域档位 | `.agents/learning-goals.md`（写明日期；用户随时可改） |
| 没懂、原来的理解 | 笔记的 Corrected Model 或 Pitfalls，并做卡片 |
| 个人经验、项目选择及理由 | 笔记的 `My Take :mine:`，用用户原话 |
| 冲突裁决 | 直接修正笔记，不另记 |
| 只对这次处理有用的背景 | 不记 |

## 流程

1. 读取材料和 `learning-goals.md`，检索已有笔记，判断是新内容、补充还是与旧笔记冲突。
2. **核对材料**：总结可能含原文没有的内容，也可能写错。逐条核对要写进笔记的说法；错误的不收，无法核实的问用户或写成 `TODO verify: ...`。
3. 按上节提问，等用户回答。
4. **按目标写笔记**（`cc-note-writing`；优先合并到已有笔记，索引与验证遵循 AGENTS.md）：
   - 以目标档位和用户卡点为界：只展开该档位需要或用户问到的内容；材料里超出档位的机制、参数和 corner case 不收。
   - 「不需要」：不收，在回复里说明。
   - 「知道」：只写「问题 → 机制」及一句话说明，合并进该领域的概览笔记；没有概览笔记时新建，放进合适的大类或 `Unsorted/`。
   - 「能判断」：写核心模型、对比、判断和故障。「能写」另加核心词汇或模板代码。用户的卡点写成「原来以为 X → 实际 Y → 最小例子」。
   - 换个时间问 AI 一次就能答对、又不属于目标档位的内容不收；0 条产出是正常结果。
5. **出题巩固**：根据写好的笔记出 1–3 道题，一次一道；用户可以作答，也可以跳过。
   - 题目要能脱离笔记独立读懂，答案在笔记里能找到；「知道」档只考「什么问题 → 用什么机制」。
   - 用户答错时，先检查笔记是否没写清楚，必要时修正；答错的点按卡点记录。
   - 题目连同答案做成 Anki 卡片（`anki-cards` skill；目标 Deck 的规则以该 skill 为准）。同一个知识点只做一张卡：卡点已有卡片时不再为它出题制卡。
6. 材料处理完后删除（不归档进知识库）；若用户要保留，移到 `inbox/_archive/`。
7. 回复列出：新增或修改的笔记、生成的卡片、记录到 `learning-goals.md` 的内容、没有收录的部分及原因。
