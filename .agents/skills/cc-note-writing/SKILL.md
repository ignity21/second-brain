# 笔记写作

本 skill 决定笔记 **写什么、不写什么、谁来写**。文件位置、ID、索引树、TOC、中文排版和验证遵循根目录 [AGENTS.md](../../../AGENTS.md)。

背景：AI 能随时回答可检索的细节，笔记不再承担「存信息」，而是保存 **理解、判断、能力地图和用户自己的经验**；需要记住的内容交给 Anki 和练习。

## 流程

1. **判定类型**：每篇笔记选一个主类型，读取对应模板。混合内容按读者用途归类，例如「Python 刷题常用标准库」是库类笔记，目标档位为「能写」。

   | 类型 | 例子 | 模板 |
   |---|---|---|
   | 库 / 工具 | Polars、uv、websockets | [library.md](references/library.md) |
   | 语言特性 | MRO、asyncio、Elisp 宏 | [language.md](references/language.md) |
   | 算法 / 数据结构 | 二分、快慢指针、堆 | [algorithm.md](references/algorithm.md) |
   | 理论 / 数学 | 梯度下降、假设检验、特征值 | [theory.md](references/theory.md) |
   | 方法 / 实践 | 代码风格、数据清洗流程 | [practice.md](references/practice.md) |
   | 经验 / 坑 | 一次调试经历 | [experience.md](references/experience.md) |
   | 误解 / 判断 | 原来以为 X 其实是 Y、选型决策 | [misconception.md](references/misconception.md) |

2. **收集材料**：用户的关键点或草稿、要改写的现有笔记、全库相关笔记（用 ID 链接，不重复写）、官方文档。用户的书籍和视频原始资料不引用；需要时可在正文用一行纯文本注明书名或课程名。
3. **逐条做准入测试**（见下节），决定每条内容的去留和位置。
4. **按模板写**：模板中的章节无内容时省略，顺序可按主题调整。
5. **核对**：版本敏感的 API、默认值、行为差异要在 scratchpad 中实际运行（例如 `uv run --no-project --with <pkg> python -I check.py`），并在笔记写明核对版本。检查脚本用具体数据运行笔记中的每个示例，并用 `warnings.simplefilter("error")` 让弃用警告直接失败。无法核对的说法不写，或写成 `TODO verify: ...` 并在回复中说明。
6. **回复**：说明删掉了哪几类内容、补了什么、核对结果，列出 Anki 候选；若用户的观点部分缺失，提出 1–3 个具体问题引导用户补写。

## 准入测试

对每条候选内容按顺序判断，命中即停：

0a. **回应了用户的疑问或被纠正的误解吗？**（来自处理收件箱时的问答、对话或草稿）→ 优先保留；用户没卡住的内容默认不展开。
0. **用户需要能脱手写出来吗？**（高频操作、面试、算法模板、语言核心惯用法）→ 保留，放入「核心词汇」或模板代码，作为 Anki 候选。范围要刻意收窄。
1. **能随时可靠地查到，且不需要脱手写？** → 不记，或在能力地图里留名字和一句话用途。
2. **推理、审查或选型时必须装在脑子里？** → 写进核心模型、对比或坑。
3. **关于用户自己**（决定、经历、环境、偏好）？→ 必须保留，归用户所有（见「人机分工」）。
4. **AI 容易写错**（版本漂移、旧 API、冷门默认值）？→ 写进坑或版本漂移表，写明旧写法 → 新写法。
5. **在区分相似选项？** → 写成对比表：差别 + 适用条件。

全部未命中的内容删除。资料覆盖了某个知识点，不构成保留它的理由。

## 掌握目标与载体

| 档位 | 含义 | 笔记中的位置 | 记忆载体 |
|---|---|---|---|
| 不需要 | 与用户的用途无关 | 不写 | 无 |
| 知道 | 能叫出名字，知道何时用，能向 AI 精确描述需求 | 能力地图、指针 | 笔记 |
| 能判断 | 能审查 AI 的代码、做选型、接手调试 | 核心模型、对比、坑 | 笔记 + 概念类 Anki |
| 能写 | 脱手写出来 | 核心词汇、模板代码 | 写代码类 Anki + 练习 |

档位由章节位置表达，不给单条内容打标签。各类型的默认档位见其模板；用户为领域或子领域设定的档位记录在 [`.agents/learning-goals.md`](../../learning-goals.md)，有记录时优先于模板默认。面试准备是一个单独目标，需要时把相关笔记的核心词汇汇总冲刺，不按面试标准要求所有笔记。

本 skill 不直接创建卡片；用户要求制卡时交给 `anki-cards` skill。

## 人机分工

- **`:mine:` 标签**：用户亲自写的内容放在带 `:mine:` 标签的标题下（通常是 `* My Take :mine:`，也可以是任意标题），子标题继承该标签。AI 只能修正错别字、Org 语法和中文排版，不改写措辞，不移动、不删除；认为内容有误时在回复中指出。
- **AI 不代写用户的部分**：不编造观点、偏好、经历和环境细节。用户没有写观点时省略 `My Take`，在回复中提问。
- **未加标签的用户草稿**是原始材料：AI 可以重组和改写，但不能丢失其中的信息。草稿里的个人判断和经历原样移入 `My Take :mine:`，只做轻微修整。
- 改写已有笔记时，未加 `:mine:` 的内容按原始材料处理；保留原 ID、标题和入链，旧版本由 Git 保存。
- AI 补充的模型、对比和版本说明以后可以随时重写。

## 版本标注

库、工具和语言笔记在文件的 property drawer 中写 `:VERIFIED_WITH:`，例如 `:VERIFIED_WITH: Polars 2.0.0 (2026-10-14)`，表示其中的代码和 API 已在该版本上运行核对。重新核对后更新这个属性。跨版本的行为差异写进坑或版本漂移表。

## 资料适配

- **API 导向的课程**（例如 DataCamp）：不照搬章节结构。把 API 压缩成按任务组织的核心词汇；从官方文档补上课程缺失的核心模型；保留并强化课程里区分相似选项的部分。
- **书籍和长视频**：以用户的关键点为主线，AI 补全概念、纠正错误，不复述资料。作者的框架本身就是模型时才沿用。

## 写法

- 语言跟随笔记现有语言；新笔记跟随用户草稿的语言，同一篇内保持一致。`:mine:` 内容不受此限。
- 代码示例最小且自包含；结果本身就是要点时（形状变化、边界值、默认行为），在示例下方给出结果，前后对比用表格或 `example` block。
- 对比优先用表格；一句话能说清的模型不展开成段落。
- 优先链接已有笔记，不在多篇中重复同一内容。同一文件内引用标题用 `[[*Heading][描述]]`；`[[#anchor]]` 只用于 toc-org 生成的 TOC。
- 没有固定篇幅限制，但每个章节都要通过准入测试。

## 完成标准

- 按 AGENTS.md「按改动验证」检查受影响的笔记。
- 笔记中的代码已在 `:VERIFIED_WITH:` 所写的版本上运行通过，或标记了 `TODO verify`。
- `:mine:` 内容与改写前一致（可用 `git diff` 检查）。
