# 算法 / 数据结构笔记

适用于算法、算法范式（贪心、动态规划）和数据结构。

**默认档位**：「能写」。这里的代码不是查得到的信息，而是理解的结晶，必须能默写。所以算法笔记 **以代码为正式内容**，不能只有文字描述。

## 模板

```org
:PROPERTIES:
:ID:       <uuid4>
:END:
#+title: <Algorithm Name>

* Recognition      ; 题目出现什么特征时想到它
* Core Idea        ; 核心思想和不变式：代码为什么正确
* Template         ; 能默写的最小实现，带可运行的断言
* Complexity       ; 时间、空间，以及推导依据
* Variants         ; 变体，以及相对模板改动了哪里
* Edge Cases       ; off-by-one、空输入、重复元素、溢出
* Practice         ; 代表题目：名称或编号，不抄题面
* My Take :mine:
```

## 各章节要求

- **Recognition**：写成「特征 → 想到本算法」的条目，例如「有序数组 + 找边界 → 二分」。这是面试时最先需要的能力。
- **Core Idea**：给出不变式或证明要点。例如 Floyd 判圈要写清相遇后为什么从头和相遇点同速前进会在环入口相遇。
- **Template**：
  - 默认用 Python；用户另有面试语言时跟随用户。
  - 最小且地道：不含 I/O 和无关的防御代码，变量名能表达不变式（例如 `lo`、`hi` 的开闭含义写在注释里）。
  - 带断言，覆盖普通情况和边界情况。可以写成 org-babel 代码块，提交前实际运行通过。
  - 同一问题有多种常见写法（例如二分的闭区间和半开区间）时，选一种作为主模板，其他放进 `Variants`，避免混记。
- **Practice**：列出代表题目，供练习和回顾，不在笔记里写题解全文。

## 配套

- 每个模板都是 Anki 写代码卡的候选：「写出 lower_bound」比「二分的复杂度是什么」更有价值。
- 刷题常用的语言工具（Python 的 `heapq`、`bisect`、`deque`、`Counter`、`defaultdict`、`functools.cache`）单独写一篇库类笔记，档位为「能写」。
