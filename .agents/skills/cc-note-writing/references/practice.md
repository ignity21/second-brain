# 方法 / 实践笔记

适用于编码风格、工程实践、工作流程和方法论，例如 Python 实践建议、数据清洗流程、测试策略。

**默认档位**：「能判断」——能在具体场景中判断该不该用某条原则。

## 模板

一篇笔记由多条原则组成，每条原则一个标题：

```org
:PROPERTIES:
:ID:       <uuid4>
:END:
#+title: <Domain> <Practice Topic>

* <Principle, stated as an imperative>
- Why: <理由：解决什么问题，代价是什么>
- When not: <不适用的情况>
#+begin_src <lang>
# 反例与正例，各自最小
#+end_src
- Enforcement: <可选：能否用 lint、formatter、测试或 AGENTS.md / skill 规则自动执行>

* My Take :mine:
```

流程类笔记（例如数据清洗流程）可以改为按步骤组织，每一步仍写明目的和判断依据。

## 各条要求

- **每条原则都要写理由。** 原来只有结论、没有理由的条目，AI 补出理由；补不出来，或理由依赖用户自己的场景时，在回复中询问用户，不凭空编造。
- **写明不适用的情况。** 没有边界的原则容易被机械套用。
- **能自动执行就转成规则。** 能由 lint 或 formatter 检查的，在 `Enforcement` 中写明工具和规则名；能约束 AI 行为的，建议用户写进 AGENTS.md 或 skill。写成规则后，笔记里保留理由即可，不必重复规则细节。
- **示例**：用最小的反例和正例对比展示，不写长段落。

## 不记

- 只是罗列冷门 API 的「技巧」：属于库类笔记的能力地图，或直接删除。
- 不带理由的个人习惯：除非用户把它写进 `My Take`。
