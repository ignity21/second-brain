## 试用时检查

- 选择文件：`inbox/` 根下有多个文件时是否让用户选，且不碰子目录。
- 提问：领域/档位问题是否在 review 前一次问清且不超过 3 个；已记录的领域有没有被重复问；有没有问 AI 本该自己核实的事。
- review 分块：是否按小节分块、一次一块，块的大小是否合适；「剩下都没问题」能否直接跳到收口。
- review 判断：每块是否附核对结论和拟收 / 不收；有问题的部分是否就地讨论、结论写回该块后才进入下一块。
- 预处理稿：错误是否改正、不收的是否删掉、卡点和想法是否以 `> 卡点：` / `> 想法：` 用用户原话写入；review 期间有没有提前写笔记。
- 收口：用户分批给卡点时，写笔记前是否确认过「还有要补充的吗」，得到确认才继续。
- 产出量：笔记是否以预处理稿为输入、按档位收敛，有没有把整篇材料重新整理一遍；0 条产出时是否说明原因。
- 卡点：错误理解是否进了误解章节、答不上来的是否只在正文写透（不在误解章节复述）；是否只做了一张卡、没有再为它出题；有没有把用户的想法写成误解。
- My Take：是否归纳润饰成易懂透彻的说法，且没有添加用户没表达过的观点。
- 格式：预处理稿的 Markdown（`>`、反引号）是否转成了 Org；笔记和卡片是否跑了 AGENTS.md 的行内标记检查，且该加的代码标记没有为躲检查省掉。
- 精度：边界条件、默认值（上游默认 vs 本机配置）是否核对过。
- 出题：是否一次一道；题目脱离笔记能读懂；答错后是否先检查笔记。
- 验证：是否作为独立步骤执行；新笔记的 TOC 标题行、ID 链接、主索引树可达性、标题重名；`org-roam-db-sync` 是否执行或说明未执行。
- 收尾：归档的是否是预处理稿，PDF 等原件是否一并移走；超过 10 天的归档是否清理；最终回复是否列全（笔记、卡片、`learning-goals.md`、未收录及原因）。

## 第二轮附加试用：show-me

在 `tcp2.md` 的 review 中试用全局 skill `show-me`（`~/.claude/skills/show-me/SKILL.md`），讲得清楚、好用再引入流程。试用期间不改 AGENTS.md 和 skills。

- 触发：用户卡住时手动 `/show-me`，或 AI 在用户说「不懂」时主动使用。重点试滑动窗口、拥塞控制（慢启动 → 拥塞避免 → 丢包后减半）这类随时间变化的过程。
- 表示约定：对话里用 ASCII（终端不渲染 Mermaid）；预处理稿和笔记用 PlantUML；动态过程可做单个 HTML 演示，放 scratchpad，不入库。
- 已知问题：skill 用 macOS 的 `open` 打开 HTML，本机要用 `xdg-open`；它的组件树、文件树、调用栈示例面向代码，笔记流程基本用不到，有用的是伪代码、时序 / 状态图和 HTML。
- 能否入笔记和卡片：伪代码和静态图能（笔记用 PlantUML，卡片用 PlantUML 导出的 PNG / SVG 加 `[[file:...]]`）；HTML 交互演示嵌不进去，Org 只能链接，Anki 跑不了。
- 若要保留某个 HTML 演示：放在大类资源子目录（如 `roamnotes-v2/Network/demos/`）或 `projects/`，笔记用 `[[file:...]]` 链接并附一张静态图，不打开 HTML 也能看懂。未核实：org-roam-ui 发布（`publish/`）是否会导出这类 HTML。
- 判断标准：图示是否让卡住的点比文字讲解更快讲清；画面是否准确（动态演示画错比文字错更易记住错误模型，flash 模型风险更高）；结论最后是否落成了笔记里的 PlantUML 或卡片；有没有给不需要图的简单事实也画图。
- 结论写入下方「试用记录」，决定是否在 AGENTS.md「入库与学习辅助」的「换表示」处引入 show-me。
