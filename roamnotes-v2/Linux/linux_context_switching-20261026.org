#+title: Linux Context Switching
#+filetags: :Linux:

* 几种切换
上下文切换（context switch）指 CPU 从一个任务换到另一个任务：保存当前任务的寄存器等状态，加载下一个任务的状态。常被混在一起的几种情况：

| 情况 | 触发 | 是否换任务 | 是否换地址空间 |
|---|---|---|---|
| 特权模式切换（mode switch） | 系统调用、中断、异常 | 否，仍是同一个任务在内核态执行 | 否 |
| 同一进程的线程之间 | 调度 | 是 | 否：只换寄存器、栈指针、TLS 等 |
| 不同进程之间 | 调度 | 是 | 是：换页表，TLB 中的旧映射失效（PCID 可减少刷新） |
| 中断 | 硬件事件 | 否：处理完回到被打断的任务，除非处理中唤醒了更高优先级的任务 | 否 |

- 一次系统调用是两次特权模式切换（进入、返回内核），不是上下文切换， ~vmstat~ 的 =cs= 也不计入。系统调用的路径和代价见 [[id:b740640d-e1b6-4d3e-a151-44653e269df7][Linux System Calls]]。
- 阻塞的系统调用（等 I/O、等锁）会让任务睡眠，这时才发生真正的上下文切换。
- 中断的处理位置和优先级见 [[id:18ebf2c0-c945-4bbc-ad58-9477849c7bbb][Linux Interrupts and Softirqs]]。

* 代价
- 直接代价：保存和恢复状态、运行调度器，微秒级。本机用管道让两个进程在同一个核上来回传 1 字节，每次往返约 5.3 µs，即每次切换（含唤醒和读写管道的系统调用）约 2.6 µs。
- 间接代价通常更大：新任务的数据不在 L1 / L2 缓存和 TLB 中，切换后一段时间都在补 cache miss。
- 低延迟系统因此让关键线程独占核、忙轮询而不睡眠，以 100% 的 CPU 占用换取不发生切换。

* 自愿与非自愿切换
| 类型 | 原因 | 变多说明 |
|---|---|---|
| 自愿（voluntary） | 任务拿不到资源，主动睡眠：I/O、锁、 ~sleep~ | 任务在等资源：I/O 慢或锁竞争 |
| 非自愿（nonvoluntary） | 时间片用完或被更高优先级任务抢占 | 可运行的任务多于 CPU，在争抢 CPU |

中断次数变多则说明 CPU 时间被中断处理占用，要到 =/proc/interrupts= 看是哪类中断在涨。

* 观测
| 范围 | 命令 | 读哪个指标 |
|---|---|---|
| 系统整体 | ~vmstat 1~ | =cs= 每秒上下文切换次数、 =in= 每秒中断次数、 =r= 运行队列长度（持续大于核数即 CPU 饱和）、 =b= 不可中断睡眠的任务数 |
| 每个进程 | ~pidstat -w 1~ | =cswch/s= 自愿、 =nvcswch/s= 非自愿；默认只统计主线程，加 ~-t~ 看每个线程 |
| 单个任务累计 | =/proc/<pid>/status= | ~voluntary_ctxt_switches~ 、 ~nonvoluntary_ctxt_switches~ |

切换次数没有绝对的好坏阈值：先和正常时的基线比，再按上表判断是在等资源还是在抢 CPU。
