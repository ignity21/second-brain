#+title: Linux Processes vs Threads
#+filetags: :Linux:

* 核心模型：内核里只有任务
- 进程和线程在内核中都是任务（task，即 ~task_struct~ ），都由 ~clone()~ 创建，区别只在共享哪些资源：
  - ~fork()~ 不传共享标志，子进程得到父进程资源的副本（内存写时复制）。
  - ~pthread_create()~ 传 ~CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD~ 等标志，新任务与创建者共享地址空间、文件描述符表和信号处理函数。
- *线程是调度的基本单位，进程是资源拥有的基本单位* 。调度器只看任务；进程是一组共享地址空间等资源的任务。
- 标识：每个任务有自己的 TID；同一进程的线程共享 TGID（线程组 ID）， ~getpid()~ 返回的其实是 TGID，主线程的 TID 等于 PID。线程在 =/proc/<pid>/task/<tid>/= 下各有一个目录，用 ~ps -L~ 或 ~top -H~ 按线程查看。每个线程有自己的状态（见 [[id:925ecbf4-455e-437d-a1bb-432542685263][Linux Process States]]）。

* 共享与私有
| 同一进程的线程共享 | 每个线程私有 |
|---|---|
| 地址空间：代码、全局变量、堆、 ~mmap~ 区域 | 栈、寄存器 |
| 文件描述符表、当前目录 | 线程局部存储（ ~errno~ 也在其中） |
| 信号处理函数 | 信号掩码 |
| PID、资源限制 | 调度策略、优先级、CPU 亲和性 |

调度属性是每线程的：线程 A 调用 ~sched_setaffinity(0, ...)~ 只绑定 A 自己，主线程仍可在所有核上运行（本机已验证）。所以低延迟程序要逐个线程绑核。

* 代价
本机（i5-1155G7）每轮实测：

| 操作 | 耗时 |
|---|---|
| ~fork~ + ~_exit~ + ~waitpid~ ，小进程 | 约 96 µs |
| 同上，父进程触碰过 1 GiB 堆 | 约 21 ms |
| ~pthread_create~ + ~pthread_join~ | 约 15 µs |

- 线程创建比进程快多少取决于地址空间大小：小进程约 6 倍，大进程可差三个数量级，因为 ~fork~ 要复制页表。
- 同一进程的线程之间切换不用换地址空间，比进程间切换便宜，见 [[id:706d7e91-8a8f-466f-b871-602e2efcd187][Linux Context Switching]]。
- 热路径上不创建线程或进程：启动时建好线程池或专用线程。

* 如何选择
| 需求 | 选择 | 原因 |
|---|---|---|
| 组件之间频繁交换数据、要求低延迟交接 | 线程 | 共享内存直接读写，无需拷贝和系统调用 |
| 一个组件崩溃不能拖垮其他组件 | 进程 | 线程中的段错误会杀死整个进程 |
| 不同语言、不同权限，或要独立重启和升级 | 进程 | 地址空间、凭据和生命周期互相独立 |
| 既要隔离又要快速交换数据 | 进程 + 共享内存 | 隔离靠进程，数据通道靠 [[id:681a06e2-6aad-4c49-881c-286cc53542f0][共享内存]] |

坑：发给进程的信号由任意一个没有屏蔽它的线程处理。多线程程序通常在所有线程中屏蔽信号，再由一个专门的线程用 ~sigwait~ 或 ~signalfd~ 处理。
