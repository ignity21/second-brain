#+title: Conan 2
#+filetags: :C++:Build:

* Positioning
A package manager for C and C++: it fetches dependencies (from ConanCenter or a private server), builds or downloads *pre-compiled binaries* matching your settings, and generates the files your build system needs to find them. Each package keeps its own build system. The main alternative is vcpkg; choose Conan when you need binary caching across many configurations or a private package server.

* Mental Model
- A *binary* is identified by the package version plus a hash of its *settings* (os, arch, compiler and version, ~compiler.cppstd~, ~build_type~) and *options* (e.g. ~shared=True~). Install looks up that exact binary; ~--build=missing~ builds it from source when none exists.
- A *profile* holds your settings. ~conan profile detect~ writes a default one from the local toolchain (here: ~compiler=gcc~, ~compiler.version=16~, ~compiler.cppstd=gnu20~, ~build_type=Release~). Debug builds, another compiler or another standard are separate profiles or ~-s~ overrides, and produce separate binaries.
- Conan does not drive the build. Its *generators* write files for CMake: ~CMakeDeps~ (one ~<pkg>-config.cmake~ per dependency, so ~find_package~ works) and ~CMakeToolchain~ (~conan_toolchain.cmake~ plus ~CMakePresets.json~ carrying the profile's compiler and flags).

* Core Vocabulary
| Task                        | Code                                                                              |
|-----------------------------+-----------------------------------------------------------------------------------|
| default profile             | ~conan profile detect~                                                            |
| find a package version      | ~conan search zlib -r conancenter~                                                |
| declare dependencies        | ~conanfile.txt~ with ~[requires]~ (~zlib/1.3.1~), ~[generators]~ (~CMakeDeps~, ~CMakeToolchain~), optionally ~[tool_requires]~ and ~[options]~ |
| install                     | ~conan install . --output-folder=build --build=missing~                           |
| debug variant               | add ~-s build_type=Debug~ (or ~-pr debug_profile~)                                |
| shared libraries            | ~-o "*:shared=True"~ (or ~-o zlib/*:shared=True~ for one package)                 |
| configure and build         | ~cmake --preset conan-release~ then ~cmake --build --preset conan-release~; or ~cmake -B build -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake -DCMAKE_BUILD_TYPE=Release~ |

In ~CMakeLists.txt~ the dependency is then an ordinary package: ~find_package(ZLIB REQUIRED)~ and ~target_link_libraries(app PRIVATE ZLIB::ZLIB)~ ([[id:c21b1c17-614b-4fb3-b0d4-bf0f4acaa2f5][CMake]]).

* Distinctions
| Section            | For                                                                                     |
|--------------------+-----------------------------------------------------------------------------------------|
| ~requires~         | libraries linked into your program                                                      |
| ~tool_requires~    | tools used during the build (a pinned ~cmake~, ~protobuf~ compiler); not for libraries   |
| settings           | project-wide, describe the machine and toolchain; part of every binary's identity      |
| options            | per-package choices with recipe defaults (~shared~, ~fPIC~, feature flags)              |

~conanfile.txt~ is enough to consume packages; ~conanfile.py~ (a ~ConanFile~ class) is needed for conditional logic or for creating packages.

* Pitfalls
- Shared dependencies must be found at run time: ~source build/conanrun.sh~ sets ~LD_LIBRARY_PATH~ for the session (~ldd~ to check), and ~conanbuild.sh~ puts ~tool_requires~ executables on ~PATH~.
- Building with a different compiler or standard than the profile says → ABI mismatches or link errors; keep the profile and the CMake configuration in sync by using the generated preset or toolchain file.
- Conan 1 tutorials (~conan install .. -g cmake~, ~CONAN_PKG::~ targets, ~conanbuildinfo.cmake~) do not apply to Conan 2.
