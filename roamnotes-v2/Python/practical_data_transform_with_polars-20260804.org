* Missing Values
** Finding nulls
- Count nulls in every column with ~df.null_count()~
- Find rows where a column is null using ~df.filter(pl.col("price").is_null())~

** Removing nulls
- ~df.drop_nulls()~ removes rows containing a null in any column.
- ~df.drop_nulls(subset="singles")~ check only selected columns

** Filling nulls
- ~df.with_columns(pl.col("singles").fill_null(0))~
- ~df.with_columns(pl.col("review").fill_null(pl.col("review").mean()))~

* Duplicates
** Finding Duplicates
- ~df.filter(df.is_duplicated())~: display duplicated rows
- ~df.filter(pl.col("name").is_duplicated())~

** Removing Duplicates
- ~df.unique()~ keeps one copy of each fully duplicated row.
- ~df.unique(subset=["name", "gender"])~

* Value Counts
- ~series.value_counts(sort=True)~

** Visualization
#+begin_src python
import plotly.express as px
count_data = sales["category"].value_counts()
px.bar(count_data, x="category", y="count", title="...")
#+end_src
* Grouping and Aggregating
#+begin_src python
df.group_by("type", maintain_order=True).agg(
    pl.col("price").mean()
).sort("price")

df.group_by("type").agg(
    pl.col("price").mean().name.suffix("_mean"),
    pl.col("price").max().name.suffix("_max"),
)

# Grouping by multiple columns
df.group_by("type", "bedrooms").agg(
    pl.col("price").mean(),
    pl.len(), # count rows in group
)
#+end_src

* Pivoting and Unpivoting
** Core Idea

~pivot~ and ~unpivot~ convert data between two common layouts:

#+begin_example
Long format --pivot--> Wide format
Wide format --unpivot--> Long format
#+end_example

Long format: categories are stored as values in a column.
Wide format: categories are spread across multiple columns.

#+begin_quote
Use long format for analysis and wide format for presentation.
#+end_quote

** Pivot

- Turn the unique values of one column into new columns.

*** Before: Long Format

| Month | Product | Sales |
|-------+---------+-------|
| Jan   | Apple   |   100 |
| Jan   | Banana  |    80 |
| Feb   | Apple   |   120 |
| Feb   | Banana  |    90 |

*** After: Wide Format

| Month | Apple | Banana |
|-------+-------+--------|
| Jan   |   100 |     80 |
| Feb   |   120 |     90 |

#+begin_src python
df.pivot(
    on="Product",
    index="Month",
    values="Sales",
    # aggregate_function=...
)
#+end_src

Pivoted data is commonly used for
- reports
- dashboards
- spreadsheets
- comparison tables.

Think of ~pivot~ as expanding categories into columns.

** Unpivot

- Reverse a pivot by collecting multiple columns into rows.

#+begin_src python
df.unpivot(
    on=["Apple", "Banana"],
    index="Month",
    variable_name="Product", 
    value_name="Sales",
)
#+end_src

This converts the data back into long format:

| Month | Product | Sales |
|-------+---------+-------|
| Jan   | Apple   |   100 |
| Jan   | Banana  |    80 |
| Feb   | Apple   |   120 |
| Feb   | Banana  |    90 |

** Summary
~pivot~: categories become columns.
~unpivot~: columns become category values.

*** Long Format is Usually Better for
- Filtering
- Grouping
- Aggregation
- Visualization
- Statistical analysis
- Machine learning
  
*** Wide Format is Usually Better for
- Reports
- Spreadsheets
- Dashboards
- Pivot tables
- Human-readable comparisons
* Text Transformation
** Casting Data Type
  - ~df.with_columns(pl.col("rating").cast(pl.Int64))~
  - Cast multiple column types: ~df.cast({pl.Float64: pl.Int64})~

** Cleaning Text
- String operations are available through the ~.str~ namespace.
  - ~df.with_columns(pl.col("business").str.strip_chars_start())~

** Creating an Identifier
#+begin_src python
df.with_columns(
    pl.concat_str(
        "business",
        "location",
        separator=", "
    ).alias("id")
)
#+end_src
- This creates a composite identifier, not automatically a unique ID. Uniqueness
  depends on the ~business~/~location~ pair being unique and the separator not
  creating collisions.

** Searching Text

~str.contains()~ checks whether each string contains a matching pattern.
The pattern is case-sensitive by default.

#+begin_src python
ratings.with_columns(
    pl.col("business")
    .str.contains("Burger")
    .alias("is_burger"),

    pl.col("business")
    .str.to_lowercase()
    .str.contains("burger")
    .alias("is_burger_case_insensitive"),
)
#+end_src

- ~"Burger"~ only matches text with the same capitalization.
- For case-insensitive matching, convert both the text and the search pattern to lowercase.
- ~str.contains()~ treats its argument as a regular expression by default.

** Extracting Text

~str.extract()~ extracts text matched by a regular-expression capture group.

#+begin_src python
ratings.with_columns(
    pl.col("business")
    .str.extract(r"(burger|coffee)")
    .alias("food"),
)
#+end_src

- ~(burger|coffee)~ is a regular expression.
- Parentheses define the capture group to extract.
- Rows without a match return ~null~.

** Filtering Text Matches

Use ~filter()~ with ~str.contains()~ to keep only rows whose text matches the pattern.

#+begin_src python
ratings.filter(
    pl.col("business")
    .str.to_lowercase()
    .str.contains("burger")
)
#+end_src

** Replacing Text
#+begin_src python
df.with_columns(
    # Replace the first literal occurrence in each string
    pl.col("location").str.replace("Rd.", "Road", literal=True),
    
    # Replace multiple substrings
    pl.col("address").str.replace_many(["Rd.", "St."], ["Road", "Street"]),

    # Replace an entire value (Value replacement)
    pl.col("type").replace("café", "restaurant")
)
#+end_src

** Categorizing Numeric Values

Convert numerical values into discrete categories.

** ~when-then-otherwise~

General conditional categorization, similar to ~if-elif-else~.

#+begin_src python
ratings.with_columns(
    pl.when(pl.col("capacity") > 100)
    .then(pl.lit("Large"))
    .when(pl.col("capacity") >= 20)
    .then(pl.lit("Medium"))
    .otherwise(pl.lit("Small"))
    .alias("venue_size")
)
#+end_src

Useful when the conditions are complex or not purely based on numeric intervals.

For simple numeric ranges, ~cut~ / ~qcut~ are cleaner.

** Fixed Thresholds — ~cut~

Split values using predefined numeric boundaries.

#+begin_src python
df.with_columns(
    pl.col("score").cut(
        [40, 70],
        labels=["low", "medium", "high"]
    ).alias("category")
)
#+end_src

#+begin_example
score <= 40        → low
40 < score <= 70   → medium
score > 70         → high
#+end_example

The thresholds stay the same regardless of the data distribution.

Use ~cut~ when boundaries have real meaning, such as:

#+begin_example
age    → child / adult / senior
income → low / medium / high
rating → poor / average / good
#+end_example

** Quantile Thresholds — ~qcut~

Split values according to their position in the data distribution.

#+begin_src python
df.with_columns(
    pl.col("score").qcut(
        [0.25, 0.75],
        labels=["low", "medium", "high"]
    ).alias("category")
)
#+end_src

- ~0.25~ → 25th percentile
- ~0.75~ → 75th percentile

#+begin_example
bottom 25% → low
middle 50% → medium
top 25%    → high
#+end_example

The actual numeric boundaries are calculated from the data and may change when the dataset changes.

** Comparison

| Method                  | Thresholds        | Use Case                          |
|-------------------------+-------------------+-----------------------------------|
| ~when-then-otherwise~   | arbitrary logic   | complex/custom conditions         |
| ~cut~                   | fixed values      | meaningful absolute boundaries    |
| ~qcut~                  | quantiles         | relative position / ranking       |

#+begin_example
cut  = divide by actual values
qcut = divide by position in the distribution
#+end_example
* Ranks, Correlations and Summary Statistics
** Ranking

Use ~rank()~ to calculate the position of each value.

#+begin_src python
df.with_columns(
    pl.col("price")
    .rank(descending=False) # method=average
    .alias("rank_default"),
    pl.col("price")
    .rank(method="min", descending=False)
    .alias("rank_min"),
)
#+end_src

- ~descending=False~: smallest value gets rank 1.
- Default tie handling uses the *average rank*. It's good for analytics

Example:

#+begin_example
price   rank
10      1.5
10      1.5
20      3.0
#+end_example
- ~method="min"~: tied values receive the lowest rank they occupy.
- ~min~ is useful for top-N displays

** Correlation Matrix

~corr()~ calculates pairwise correlations between numeric columns.

#+begin_src python
corr = (
user_reviews
.select(pl.selectors.integer())
.corr()
)
#+end_src

The result is a square matrix:

#+begin_example
user_1  user_2  user_3
1.00    0.82    0.15
0.82    1.00    0.30
0.15    0.30    1.00
#+end_example

The columns identify the variables, but Polars does not automatically create a corresponding row-label column.

To make the matrix easier to read:

#+begin_src python
corr = corr.with_columns(
pl.Series("user", corr.columns)
)
#+end_src

Now the result becomes conceptually:

#+begin_example
user    user_1  user_2  user_3
user_1  1.00    0.82    0.15
user_2  0.82    1.00    0.30
user_3  0.15    0.30    1.00
#+end_example

Why does ~pl.Series("user", corr.columns)~ work?

~corr.columns~ returns the column names:
#+begin_src python
["user_1", "user_2", "user_3"]
#+end_src

Correlation values range from ~-1~ to ~1~:

- ~1~ → strong positive linear relationship
- ~0~ → little/no linear relationship
- ~-1~ → strong negative linear relationship

** Custom Summary Statistics

~describe()~ can use custom percentiles:

#+begin_src python
spotify.select("popularity", "monthly_listeners").describe(
    percentiles=[0.1, 0.9]
)
#+end_src

Useful when the analysis already uses specific quantile thresholds and the summary should show the same cut points.
