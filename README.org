* 目录

- =roamnotes-v2/= ：org-roam 笔记库；=roamnotes/= 是待迁移的旧版笔记。
- =ankinotes/= ：Anki 卡片。
- =projects/= 、=notebooks/= ：配合笔记的示例代码与 notebook。
- =inbox/= ：学习材料暂存区（gitignore）；处理后的材料移到 =inbox/archive/= 。
- =publish/= ：在线图谱的导出与构建脚本。
- =.agents/= ：AI 协作用的 skills 与任务记录；协作约定见 =AGENTS.md= 。

* 学习流程

1. 读网页时，用浏览器的「summarize page」生成总结，直接存为 =inbox/<名字>.md= 。非网页材料（文稿、幻灯片）也存成单个文件，放在 =inbox/= 根下，不建子目录。
2. 在仓库里对 AI 说「处理收件箱」。根下有多个文件时，AI 会列出来让你选，子目录不管。领域目标、档位这类问题 AI 会在开始前一次问清。
3. AI 按小节逐块 review 原材料，每块附上核对结论和拟收 / 不收；你提出卡点或意见，讨论结论直接改进原材料（改错、删掉不收的、写入你的卡点和想法）。说「剩下都没问题」可跳到最后。走完后 AI 确认卡点是否都提完了。
4. AI 以改好的材料为输入，按学习目标（ =.agents/learning-goals.md= ）写笔记（必要时并入已有笔记），写完再按笔记出题，题目做成 Anki 卡片。
5. 处理完成后，改好的材料移到 =inbox/archive/YYYYmmdd/= ；超过 10 天的归档会被删除。

* 分类、索引与重名约定

- 一级目录是笔记的主要入口，不是互斥的身份标签；应作为主题的粗粒度分类使用，而非依赖大量 tag。
- 笔记的身份由 UUID v4 的 =:ID:= 和 =[[id:...]]= 链接决定。目录与索引是可重构的导航层：每篇笔记选择一个主索引归属，其他主题关系通过正文链接表达，而不复制内容。
- 跨目录移动笔记后，检查相对图片链接（如 =[[file:images/...]]= ）是否仍能正确解析。
- 同名但语言或领域不同的笔记，主标题使用可区分的名称，如 =C++ Code Conventions= 与 =Python Code Conventions= ；
  - 在所属中间层级索引中可显示简短链接名 =Code Conventions= 。
- 中间层级节点也使用带领域上下文的标题，例如节点标题用 =Emacs Lisp Core Language=，上级链接描述可以只显示 =Core Language= 。
- 只要一个分组代表真实的知识层级，就为它建立带 UUID 的节点；不要只用普通 Org 标题隐藏图谱层级。
- 主索引结构保持为一棵树：每个节点默认只有一个主父节点，跨主题关系通过正文链接表达。
- 单个索引节点建议连接 2–8 个下一层节点；出度过大时增加语义明确的中间节点，而不是增加文件目录。
- 重构时保留语义未变化节点的 UUID，并检查索引可达性、唯一主归属、标题重名和相对资源链接。
- 不要为不同笔记设置相同的 =:ROAM_ALIASES:=。若存在真正跨语言、跨领域的通用主题，单独建立一个主题节点，并由具体笔记链接到它。
