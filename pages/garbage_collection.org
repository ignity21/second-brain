#+TITLE: Garbage Collection

- tags :: [[id:9eb7595a-bf63-4a94-9a41-30442f6be45a][Memory Allocation]], [[id:33973869-8b9b-4458-8507-be5b14ebd339][Memory]], [[id:a4d6ea49-ad7b-48f8-8f5d-f5510e7ef392][Out of Memory]], [[id:62289ff0-f3b6-402f-b6bc-6fd33cd8ca44][Page Cache]], [[id:fbf5ab03-e642-4aab-97db-37c8a2b53f58][Swap]], [[id:4c3c913d-e201-4937-aca5-11d86f37fac1][Dirty Pages]]


系统也不会任由某个进程用完所有内存。在发现内存紧张时，系统就会通过一系列机制来回收内存，比如下面这三种方式：
- 回收缓存，比如使用 LRU 算法。
- 回收不常访问的内存，把不常用的内存通过交换分区（SWAP）直接写到磁盘中。
- 杀死进程，内存紧张时系统还会通过 [[id:a4d6ea49-ad7b-48f8-8f5d-f5510e7ef392][OOM（Out of Memory）]] ，直接杀掉占用大量内存的进程。

* 内存回收时机
- 直接内存回收 :: 有新的大块内存分配请求，但是剩余内存不足。这个时候系统就需要回收一部分内存。
- 系统定期回收 :: 由内核线程 ~kswapd0~ 定期回收内存

** ~kswapd0~ 内存回收机制
- 内存阈值 (watermark) ： =pages_min=, =pages_low=, =pages_high=
- 剩余内存： =page_free=
- 可通过 [[id:38af873a-9c66-453a-b0ef-8f7213b6935c][=/proc/zoneinfo=]] 查看

- 剩余内存小于 =pages_min= ： 仅内核可分配内存
- 剩余内存介于 =pages_min= 和 =page_low= 之间： ~kswapd0~ 会执行内存回收，直到剩余内存大于高阈值为止
- 剩余内存介于 =pages_low= 和 =page_high= 之间：内存有一定压力，但还可以满足新内存请求。
- 剩余内存高于 =pages_high= ： 内存无压力

=pages_min= 可通过内核选项 [[id:c6678eb9-f47b-4db1-b9b8-1c3c363229b0][=/proc/sys/vm/min_free_kbytes=]] 修改。
- $pages\_low=\frac{5}{4}\times pages\_min$,
- $pages\_high=\frac{3}{2}\times pages\_min$

** [[id:aafc265a-67a8-49e0-9e11-4615ae4fe19d][NUMA]]相关
某个 Node 内存不足时，系统可以从其他 Node 寻找空闲内存，也可以从本地内存中回收内存，
具体模式可通过 =/proc/sys/vm/zone_reclaim_mode= 调整。
- 0: 默认值。表示既可以从其他 Node 寻找空闲内存，也可以从本地回收内存
- 1: 回收本地内存
- 2: *可以回写脏数据回收内存*
- 4: 可使用 [[id:fbf5ab03-e642-4aab-97db-37c8a2b53f58][Swap]] 方式回收内存

* 堆内存
- 堆内存由应用程序动态分配，也就是我们在内存管理中说到的匿名页（Anonymous Page）。
- 堆内存只能由应用程序释放内存
- 堆内存可以被放入[[id:fbf5ab03-e642-4aab-97db-37c8a2b53f58][Swap]]中，释放实际内存

* 总结
- 文件页回收 :: 直接回收缓存，或者把脏页写回磁盘后再回收。
- 匿名页回收 :: 通过 [[id:fbf5ab03-e642-4aab-97db-37c8a2b53f58][Swap]] 机制，把它们写入磁盘后再释放内存。
