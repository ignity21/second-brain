#+title: Context Switching
#+filetags: Linux
* Mode Switch
:PROPERTIES:
:ID:       d79d72f5-8bf8-44c5-9ec4-e426e657c4b7
:END:
系统调用将进程从用户态转变到内核态，为了执行内核态代码， CPU 寄存器需要更新内核态指令的上下文，调用结束后再切换到用户空间，该过程通常称为特权模式切换 (*mode switch*)。
- 需保存和恢复 CPU 的 *寄存器* 、 *Program Counter(PC)* 的状态。
- 一次系统调用，发生了两次 CPU 上下文切换。

* 进程上下文切换
:PROPERTIES:
:ID:       76f53542-02f4-4ed7-8fd5-3bd7aaadc721
:END:
进程的上下文包括
- 用户空间资源 :: 虚拟内存、栈、全局变量、TLB(Translation Lookaside Buffer) 等
- 内核空间资源 :: 内核堆栈、寄存器等

** 进程调度队列
- 调度规则： 优先级高、等待 CPU 时间长的进程优先被调度


*** 发生调度场景
1. CPU 时间被划分为时间片，轮流分配公平调度
2. 进程无法获得资源时被挂起，即 *自愿上下文切换*
3. 进程 sleep 主动挂起
4. 发生 [[id:d959170b-6b5b-44fd-af42-5d274c83780b][Hardware Interrupt]] 时，运行中的进程会被中断挂起，CPU 转而执行中断处理程序

* 线程上下文切换
线程与进程最大的区别在于： *线程是调度的基本单位，而进程则是资源拥有的基本单位。* 所谓内核中的任务调度，实际上的调度对象是线程；而进程只是给线程提供了虚拟内存、全局变量等资源。

- 当进程拥有多个线程时，这些线程会共享相同的虚拟内存和全局变量等资源，同进程内线程上下文切换时不需要修改。
- 线程也有自己的私有数据，比如栈和寄存器等，这些在上下文切换时也是需要保存和恢复。

* [[id:18ebf2c0-c945-4bbc-ad58-9477849c7bbb][中断]]上下文切换
为了快速响应硬件的事件， *中断处理会打断进程的正常调度和执行* ，转而调用中断处理程序响应设备事件。
- 对同一个 CPU 来说， *中断处理比进程拥有更高的优先级* ，大部分中断处理程序都 *短小精悍* 。
- 中断上下文指的是包括内核态中断服务程序执行所必需的状态，包括 CPU 寄存器、内核堆栈、硬件中断参数等。

** 内核中断相关配置
- 内核调度中断频率配置 ~grep 'CONFIG_HZ=' /boot/config-$(uname -r)~ 250Hz，即每秒钟触发 250 次时间中断
- 用户节拍率 USER_HZ 总是固定为 100Hz， 即10ms一次时间中断

* 检查上下文切换情况
- 系统整体 [[id:23925da8-c185-47a2-bc40-9e94f9fdaf8e][~vmstat --unit=M 5~]]
  - cs (context switch) 每秒上下文切换次数
  - in (interrupt) 每秒中断次数
  - r (Running or Runnable) 就绪队列长度
- 单个进程 [[id:4baf76c7-7bd5-4bf4-b573-86b0dabd4869][~pidstat -w 5~]]
  - cswch/s: voluntary context switches 无法获得资源发生的上下文切换
  - nvcswch/s: non voluntary context switches 运行时间片已到，被系统强制调度
