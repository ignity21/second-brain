#+title: Database Sharding
#+filetags: SystemDesign

* Overview
Sharding is the act of splitting a large database into smaller pieces called shards.
- also called *data partitioning*

* Considerations
- Choosing appropriate *sharding key that can evenly distributed data*
- Using [[id:3237b43a-1ce2-438a-8db3-f5ed52cecd7d][Consistent Hashing]] to solve resharding data problem.
- Celebrity problem (hotspot key problem)
  - may need to allocate *a shard for each celebrity*
- Hard to perform join operations across database shards.
  - common workaround: de-normalize the database so queries can be performed in a single table.

* Sharding Strategies
- based on a client's region
- based on the type of data being stored (e.g: user data in one shard, payments data in another shard)
- based on the hash of a column (only for structured data)
