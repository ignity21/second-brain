#+TITLE: Network

* TCP/IP 四层
** 传输层
- 负责端到端的通信

** 网络层
- 负责网络包的封装、寻址和路由

** 网络接口层
- 负责网络包在物理网络中的传输，比如 MAC 寻址、错误侦测以及通过网卡传输网络帧等。
- *MTU* 网络接口配置的最大传输单元，规定了最大的 *IP* 包大小。
- 内核通过中断跟网卡进行交互
  - 网卡硬中断只处理最核心的网卡数据读取或发送
  - 协议栈中的大部分逻辑都放到软中断中处理

* 网络包接收流程
1. 网络帧到达网卡
2. 网卡通过 DMA 方式，把网络包放入收包队列，通过硬中断通知 硬中断处理程序
3. 中断处理程序转换网络帧为内核数据结构 sk_buff，放入 sk_buff 缓冲区
4. 通过软中断通知内核受到了新的网络栈
5. 内核协议栈从 sk_buff 缓冲区取出网络帧，通过网络协议栈逐层处理网络帧

** 链路层
1. 校验报文合法性
2. 找出上层协议类型 (IPv4 or IPv6)
3. 去帧头帧尾传给网络层

** 网络层
1. 取出 IP 头，判断网络包是交给上层处理，还是转发
2. 如交给上层，取出上层协议的类型 (TCP or UDP)，再交给传输层

** 传输层
1. 取出 TCP/UDP 头
2. 通过 < 源 IP、源端口、目的 IP、目的端口 > 找出对应的 Socket，数据拷贝到 Socket 的接收缓存中
3. 应用程序通过 Socket 接口，读取到新接收的数据

* 网络包发送流程
1. 应用程序调用 Socket API 例如 sendmsg
2. Socket层会把数据包放到 Socket 发送缓冲区
3. 网络协议栈从 Socket 发送缓冲区中取出数据包，逐层添加个层的头
4. 执行路由查找确认下一跳的 IP (网络层)
5. 按照 MTU 大小进行分片 (网络层)
6. 将分片后的网络包送到网络接口层，进行物理地址寻址，找到下一跳的 MAC 地址
7. 添加帧头帧尾，放到发包队列中，由软中断通知 *驱动程序*
8. 驱动程序通过 DMA ，从发包队列中读取网络帧，通过物理网卡发送出去
